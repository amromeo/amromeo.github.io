# Task H confirmation of the subsampling policy at N = 50,000

**Proposed for approval, 26 November 2026.** The question is whether replacing a full-data first-stage interval with the subsample median improves accuracy on datasets the package already serves, and whether the median can safely return an interval when the package withholds one. The comparator is the public anchoredRI 0.4.0 package, including its fallback. The policy, its routing order and its 50-draw median come from the RIbench review. This document fixes the confirmation cohort, scoring and proposed success criteria before any Task H calculation on that cohort. [RIbench review](../review/README.md) · [Frozen package](https://github.com/amromeo/amromeo.github.io/tree/fe8105ac6961f1b45bbfbe034648938f227c4726/anchoredRI)

## Fit and route

Use the pinned Task H runtime (R 4.5.0), pooled routine setting, automatic transformation, up to five components, recorded h, and the same 40 anchors in all fits of a dataset. Run the public full-data fit once with both safeguards and ordinary package fallback enabled. Use mixture fitting seed 1, fallback fitter seed 123 and fallback PIT seed 38000000 + j for both banks. Retain its first-stage status and its actual final result. Each subsample uses only the same first-stage mixture and its two checks. These checks are the package’s anchor likelihood-ratio flag (p < 0.01) and its lower-limit flag (lower limit below that fit’s observed routine minimum). The median itself receives no additional model check. [Task H settings and runtime](../launch-full.json) · [Package entry point](https://github.com/amromeo/amromeo.github.io/blob/fe8105ac6961f1b45bbfbe034648938f227c4726/anchoredRI/R/fit_anchored_ri.R)

For each draw b from 1 through 50, sample 5,000 positions without replacement from the full vector, sort the positions and retain the original order. Use R’s Mersenne-Twister, Inversion and Rejection settings with `sample.int`. Bank A uses seed 100000000 + 100j + b. Sensitivity bank B uses 200000000 + 100j + b. Take the median of each raw endpoint over all draws with two finite, ordered endpoints, including statistically declined draws. Omit an unusable pair from both medians and report the contributor count. A majority approves when there are at most 25 declines even if every technically unresolved vote were a decline. At least 26 observed declines gives a decline. Otherwise the vote is unresolved. All 50 draws enter each vote. [Frozen aggregation](https://github.com/amromeo/amromeo.github.io/blob/558001e46480fa101900e3d658ac68cdf56ac2db/anchoredRI/tools/subsample/aggregate.R)

Apply these routes in order, once for each bank. The package comparator is the same full-data result in both banks.

| Step | Condition | Output |
|---|---|---|
| a | Full-data first stage passes both checks | Subsample median, regardless of the majority vote |
| b | First stage did not pass and the package returns a valid interval | Exact package interval |
| c | First stage did not pass, the package withholds, and the majority approves a usable median | Subsample median |
| d | Remaining assignments | No interval |

If step a has no usable median, record a technical nonreturn there and count the lost package return. Do not change its route after seeing the comparator or truth. Distinguish completed technical withholdings from statistical declines for the package and the individual draws. A missing execution record is incomplete work. Reconcile all assignments and draws before computing gates. Arm W and the three-component variants are closed. Their existing RIbench results remain available. ## Endpoints and proposed success criteria

For each returned lower and upper endpoint x, compute the signed error z = Φ⁻¹(p) − Φ⁻¹(H(x)), using the known unrounded, support-corrected healthy CDF H and p = 0.025 or 0.975. Use the frozen Stage 2 numerical implementation. The dataset error d is the mean of the two absolute z values. A finite endpoint outside healthy support gets its boundary z, including infinite error. Count any endpoint with |z| > 5 as extreme. Report it also when the other endpoint is accurate. Both methods must have finite, ordered reported limits in measurement units. Flag invalid releases separately. [Synthetic truth and score](https://github.com/amromeo/anchorRefine/blob/c043917226b20929296b80cda53e0ae293968b42/stage2/generator.R)

The unit of analysis is one original j. Weight datasets equally. Define differences as policy minus package, so a negative difference favors the policy. Use bank A and unrounded point estimates for all gates. Bank B measures seed sensitivity and cannot replace a failed bank A result.

| Claim | Criteria fixed for this confirmation |
|---|---|
| Accuracy on common returns | On the datasets where both return an interval, mean uncapped d must be lower for the policy than for the package overall. Within each of the two pathology strata, mean paired capped error (min(d, 5)) may increase by at most 0.02 on common returns. Require comparable returns in both strata. |
| Coverage and extremes | The policy must preserve every package return by j, release no invalid interval, and have no more released intervals with an extreme endpoint than the package overall or within either pathology stratum. |
| Error including nonreturns | Over all 1,440 assignments the mean of min(d, 5), scoring each nonreturn as 5, must be lower for the policy. This criterion is in addition to the common-return comparison. |
| Added coverage from step c | At least one package nonreturn must be recovered. On these additional returns require mean uncapped d < 1 healthy z unit and zero intervals with any extreme endpoint. The threshold of 1 limits the average endpoint error allowed on returns for which the package supplies no paired interval. |

For the uncapped common-return gate, compare the two method means on the identical set under extended-real arithmetic. A finite policy mean is lower than an infinite package mean. Two infinite means cannot establish improvement. Report the cases, the capped comparison and the finite-pair mean separately. If step c never fires, record added coverage as unevaluated. Judge accuracy, coverage preservation and the all-assignment result separately, and reserve a claim for the complete four-step policy for a pass on all four rows. Report gate outcomes for B descriptively. These are criteria for this synthetic experiment at 50,000. Adopting a sample-size rule between 5,000 and 50,000 would require separate evidence.

## Reporting and verification

Report all four route counts, returns and nonreturns for each bank. Compare uncapped error on the same returned IDs with paired means, mean and median change, median absolute change, wins/ties/losses, separate nonfinite counts and endpoint extremes. Use strict comparisons of full-precision d for wins and losses. Show each method’s mean on its own returns alongside the all-assignment score. Show case-matched results by pathology stratum, exact fraction, healthy family, disease pattern and rounding. Report the same metrics for the policy ending after b so the reader can see exactly what c adds.

For step c give its denominator (all package nonreturns), number recovered, percentage, reasons the package withheld, numbers with a determined or unresolved vote, contributor and vote counts, mean and median d, maximum d, both signed endpoint errors, and every extreme. Report how often the same datasets are rescued under A and B, including individual gains and losses. Give a two-sided exact 95% binomial interval for the extreme rate among rescues, labeled descriptive for this factorial design. When few cases reach step c, report the resulting uncertainty even if its point-estimate criteria pass. If no rescue occurs, show zero and mark conditional rates and errors undefined. Give paired 95% percentile intervals for the common-return error difference and all-assignment score difference by resampling whole factorial cells (all eight replicates together, 2,000 resamples with NumPy PCG64 seed 37000000, both methods and both banks paired). List undefined bootstrap replicates. Intervals express sampling uncertainty separately from the decision rules.
